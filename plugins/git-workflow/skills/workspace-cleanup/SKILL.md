# Workspace cleanup

Everything this removes is either regenerated by a build or already on the remote.
Nothing here touches the remote. The goal is a clone that, when idle, holds the source and
its installed dependencies, and nothing else.

## 1. Build output

Find what the build and dev server leave behind: the paths in `.gitignore`, minus
dependency folders, are the usual list. Common ones:

| Path | Created by |
| --- | --- |
| `dist/`, `build/`, `out/`, `.output/` | the build |
| `.astro/`, `.nuxt/`, `.next/`, `.svelte-kit/` | framework type and content caches |
| `node_modules/.vite/`, `node_modules/.cache/` | bundler caches |
| `.wrangler/` | a local Cloudflare `wrangler` run |
| `coverage/`, `.turbo/` | test and task-runner caches |

Delete them once no dev server is using them, and only if git ignores them
(`git check-ignore -q <path>`). Leave dependency folders such as `node_modules/` alone,
unless you're about to reinstall anyway.

## 2. Worktrees

```
git fetch --prune
git worktree list
```

A worktree can go once **all** of these hold:

- Its branch's PR is merged or closed (`gh pr list --state all --head <branch>`). A
  squash merge leaves the branch looking unmerged to git, so ask GitHub rather than
  `git branch --merged`.
- `git -C <path> status --short` is empty, or you've confirmed the changes are
  disposable.
- It isn't **locked**. A lock means a running agent session still owns it, so leave it
  for that session to clean up.

Then remove it:

```
git worktree remove <path>
```

Run `git worktree prune` for entries whose directory is already gone. On Windows, a
worktree created from WSL is registered under a `/mnt/<drive>/...` path that Windows git
can't resolve, so it shows as *prunable* even though its directory exists. Remove that
directory by its Windows path, then prune.

## 3. Local branches

Delete a local branch once its PR is merged or closed and no worktree uses it:

```
git branch -D <branch>
```

`-D` is needed because git can't tell that a squash-merged branch was merged. Check the
PR state first, as in step 2.

Never delete the default branch, the branch of a remaining worktree, or a branch with
commits that exist nowhere else and no PR (`git log origin/<default>..<branch>`). Ask
first.

## 4. Keep the default branch current

If the default branch isn't checked out anywhere, fast-forward it without switching:

```
git fetch origin <default>:<default>
```
